# OctoAcme Project Management Docs

This repository contains the core project management guidance used by OctoAcme across the lifecycle of a project. The documents in this folder provide a practical framework for starting work, planning delivery, tracking execution, managing risks, releasing changes, and closing out learning. Together they create a consistent operating model for cross-functional teams and help new team members quickly understand how work is coordinated.

## Project management process summary

OctoAcme begins by validating the business problem and aligning stakeholders around the desired outcome. During initiation, teams document the problem statement, success metrics, timeline, dependencies, and initial risks so that work is grounded in a clear need and decision gate. Once approved, the team moves into planning by breaking work into a backlog, estimating scope, setting milestones, and defining the Definition of Done to make execution predictable.

During execution, teams use project boards, pull requests, daily standups, and weekly delivery reviews to track progress, manage blockers, and keep work visible. Risk, communication, and dependency management are treated as ongoing responsibilities, with escalation paths to project and product leadership when needed. The release process adds guardrails for quality and safety by requiring validation, smoke tests, release notes, and rollback readiness before changes are deployed to production.

After delivery, OctoAcme emphasizes reflection and improvement through retrospectives, action tracking, and continuous learning. This closes the loop by capturing what went well, what needs adjustment, and which actions should be prioritized for the next iteration. The roles and personas guidance supports this lifecycle by clarifying ownership and collaboration across product, project, engineering, QA, and stakeholder responsibilities.

## Roles and personas

The roles and personas document helps teams align responsibility and collaboration across each stage of the lifecycle. It defines the typical responsibilities of developers, product managers, project managers, and other stakeholders so that ownership is clear, decisions are informed, and communication stays consistent from initiation through release and improvement.
